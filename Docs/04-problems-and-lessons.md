# Проблемы и уроки

Журнал нетривиальных проблем: что случилось, почему, как решили. Сначала — общие уроки,
которые важнее отдельных багов.

## Главные уроки

1. **Не изобретать велосипед, если у автора есть рабочее решение.** Коллайдер чанков не работал
   из-за ручного формата вершин; вместо того чтобы сделать как в движке автора Voxer (обычный
   `SetVertices` и один меш на рендер и коллайдер), ИИ сначала пытался обойти проблему своим
   воксельным рейкастом. Автор: «кучу токенов потратили на изобретение велосипеда». Если
   подобное уже работает у автора (Voxer, 3D-Skyblock, Base-Defence) — сначала смотреть туда.
2. **UX не упрощать и не выдавать упрощение за решение** (правило в `CLAUDE.md`). Примеры ошибок:
   сетка застройки из залитых плиток без линий; прозрачность дизерингом вместо настоящей;
   предложение контура «раздутой копией меша». Перед UX-задачей — вспомнить, как это сделано в
   хороших играх, и делать так же; если где-то есть ограничение — сказать прямо.
3. **Не утверждать непроверенное.** Пример: ИИ заявил, что в TextMeshPro нет кириллицы, — автор
   показал, что есть. Не знаешь — проверь (в том числе исходники Unity, см. `05-workflow.md`).
4. **ИИ не может скомпилировать проект** (в облаке Unity нет, локально нет редактора 2022.3) — каждое изменение Unity-кода проверяется только автором.
   Поэтому: внимательно к API (сверять с исходниками пакета нужной версии), проверка синтаксиса
   tree-sitter, честно писать «в Unity не проверено».

## Журнал

### Шейдер: `undeclared identifier 'LerpWhiteTo'` в ShadowCaster
`Shadows.hlsl` использует `LerpWhiteTo` из `CommonMaterial.hlsl`, но сам его не подключает.
Решение: `#include ".../CommonMaterial.hlsl"` перед `Shadows.hlsl`.

### Взрыв не работал: две арены в сцене
Меню создания сцены запустили дважды. Решение: защита в меню от повторного создания.

### Взрыв не работал: пустой MeshCollider (sharedMesh = null)
Меш собирался через `SetVertexBufferParams` с нестандартным форматом вершин — такой меш
MeshCollider не принимал. Попытки лечить флагами и подмешами не помогли; воксельный рейкаст
автор отверг. Решение: обычные `SetVertices / SetNormals / SetColors / SetIndices` и один меш на
рендер и коллайдер — как в Voxer. Сработало сразу.

### Чанки пропадали при повороте камеры
Временно обнулённые `mesh.bounds` → отсечение по видимости. Решение: снова задавать bounds явно.

### `Debug` is an ambiguous reference
`System.Diagnostics` + `UnityEngine`. Решение: `using Debug = UnityEngine.Debug;`.

### NullReferenceException в `ArenaTestController.FocusOwnBase`
`Start` отрабатывал раньше генерации. Решение: проверка на `Layout == null` + подписка на `Generated`.

### Юниты не всегда находили путь к базе врага / к точкам захвата
Проверка по сетке говорила «достижимо», а NavMesh — нет (6/8, потом 7/8 точек). Причины: узкие
рампы шириной 3 и точки, поставленные до рамп. Решения: строже эрозия сетки (8 соседей, ширина
агента), убраны узкие запасные рампы, точки ставятся после рамп и только туда, куда доходит
проход шириной 3. Добавлена проверка путей по NavMesh в тестовой сцене.

### Карта — «прямоугольник из гор», базы у края
Решения: неровные горы по краю (шум, гребни, снег, туман, ограничение камеры), карта 400×400,
50 клеток поля за базой.

### Неверное время генерации в логе
Один секундомер на разные замеры. Решение: отдельный `generateTimer`.

### CS0266 в GameHud (`math.lengthsq(int2)` → float)
Решение: квадрат расстояния вручную в int.

### UX установки: «Ты где такой UX стройки видел???»
Первая версия ставила здание тапом по месту. Переделано в стиле Clash of Clans: здание сразу стоит,
тащится пальцем, кнопки над ним.

### Здание появлялось внутри главного здания
При отсутствии подходящего места (шахта без своих точек) бралась клетка под центром экрана.
Решение: поиск подходящего места в радиусе сетки, иначе ближайшее свободное, но не внутри здания.

### Здание появлялось «сразу за другой постройкой» (закрыто от камеры)
Место выбиралось только по расстоянию. Решение: ближайшее место, где здание целиком в кадре
(с местом под кнопки), не закрыто (лучи от камеры к верху и углам) и с зазором 1 клетка до других
зданий; вне кадра — камера плавно едет к зданию.

### Сетка без линий, прозрачность дизерингом
См. главные уроки, п. 2. Переделано: линии и заливка в шейдере по UV клетки; настоящая
альфа-прозрачность зданий (прозрачный материал) и стен (земля в режиме установки не рисует
пиксели стен, их рисует второй прозрачный проход по чанкам со стенами).

### Зелёная подсветка здания сливалась с зелёной сеткой
Решение: здание без заливки, экранный контур (URP Renderer Feature) зелёный/красный; остальные
здания и стены приглушаются; автор подобрал бледные цвета сетки (стали значениями по умолчанию).

### Турель можно было поставить на стену «случайно»
Проверка ровности пропускала верх стены. Сначала запретили, автор попросил вернуть как фичу —
теперь разрешено явно: только турель, только своя стена, не на зубцах.
